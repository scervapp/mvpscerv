# A-04 hosting preview workflow report

Task: A-04
Status: Done locally
Date: 2026-09-27
Deploy status: None

## Problem

The existing PR workflow was generated by Firebase Hosting and ran:

```bash
npm ci && npm run build
```

The root package has no `build` script, so the workflow was structurally broken. It also attempted a Firebase Hosting preview deploy against `projectId: scervmvp`, which conflicts with the current release-readiness posture: no production-project deploy action should happen from a PR workflow while hardening gates are still open.

## Decision

Replace the Firebase preview deploy workflow with a build-only PR workflow.

## Current workflow behavior

The workflow now:

- Installs root dependencies.
- Runs `npm run security:secret-scan`.
- Installs and builds `web-app/scervWeb`.
- Installs and builds `web-app/admin`.
- Does not deploy to Firebase Hosting.
- Does not require a Firebase service account secret.

## Evidence

Local validation completed:

| Command | Result |
| --- | --- |
| `npm run security:secret-scan` | Pass |
| `npm.cmd --prefix web-app\scervWeb run build` | Pass; generated 3 static resource pages |
| `npm.cmd --prefix web-app\admin run build` | Pass |

Both React builds emitted stale Browserslist data warnings. That is not a release blocker, but the dependency metadata should be refreshed later in a normal maintenance task.

The workflow structure is now aligned with the repo layout and the production-deploy freeze.
